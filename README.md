# SWYNEX Final Cloud Deployment

## CloudTask – Cloud Deployment Case Study

### 1. Project Overview

CloudTask is a simple task management web application developed using HTML, CSS, and JavaScript. This project demonstrates the process of hosting a web application using cloud deployment services.

This case study combines application development, cloud architecture, deployment, monitoring practices, cost awareness, and lessons learned.

### 2. Project Details

- **Project Name:** CloudTask
- **Internship:** SWYNEX Technologies
- **Frontend:** HTML, CSS, JavaScript
- **Source Code:** GitHub
- **Cloud Hosting:** Netlify
- **Deployment Branch:** main

### 4. Cloud Architecture

The application follows a simple static website deployment architecture.

```text
        User
          |
          v
     Web Browser
          |
          v
    Netlify Hosting
          |
          v
   CloudTask Website
    HTML / CSS / JS
          |
          v
   User Interaction
```

GitHub stores the application source code, while Netlify hosts the deployed website.

### 5. Deployment Process

1. Develop the CloudTask application.
2. Upload the source code to GitHub.
3. Connect the GitHub repository to Netlify.
4. Configure the deployment branch as main.
5. Deploy the website through Netlify.
6. Verify the published website using its live URL.

### 6. Monitoring and Cost Awareness

The project includes documented monitoring and cost-awareness practices.

- Check website availability using the live URL.
- Verify website functionality through manual testing.
- Review Netlify production deployment status.
- Inspect deployment logs for errors.
- Monitor hosting usage and available plan limits.
- Optimize website assets and avoid unnecessary resources.
- Follow HTTPS and basic security practices.

Refer to [Monitoring Documentation](monitoring.md) for further details.

### 7. Security Practices

- Use HTTPS for website access.
- Avoid publishing passwords, API keys, or secrets.
- Enable multi-factor authentication where available.
- Keep repository access permissions appropriate.
- Avoid storing sensitive user information.

### 8. Project Limitations

- The application is a static frontend website.
- No backend server or database is included.
- Browser localStorage data remains browser-specific.
- Deployment logs do not represent backend application logs.
- Advanced alerting must be configured separately if required.

### 9. Lessons Learned

Through this project, I learned:

- Basic cloud hosting concepts.
- GitHub repository management.
- Connecting GitHub with Netlify.
- Deploying and verifying a static website.
- Checking deployment logs and status.
- Monitoring practices and cost awareness.
- Basic cloud security practices.

### 10. Conclusion

This project provided practical experience in deploying a web application using cloud hosting services. It helped me understand the complete workflow from source code management to deployment, monitoring, and documentation.
